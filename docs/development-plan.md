# ddoniddoni-resume 개발 계획

## 1. 문서 개요

- 상태: 초안
- 작성일: 2026-08-24
- 대상 프로젝트: `ddoniddoni-resume`
- 레퍼런스: [Devraj Chatribin Projects](https://devrajchatribin.com/projects)
- 핵심 기술: Next.js 16, React 19, TypeScript, Tailwind CSS 4, App Router

이 문서는 개인 이력과 프로젝트를 소개하는 반응형 포트폴리오 사이트의 개발 목표, 범위, 구현 순서와 완료 기준을 정의한다.

레퍼런스의 어두운 배경, 강한 에디토리얼 타이포그래피, 프로젝트 탐색 구조와 연락 CTA에서 디자인 원리를 가져온다. 다만 레퍼런스의 코드, 문구, 이미지, 로고, 고유한 브랜드 표현은 복제하지 않는다. 실제 개인 정보와 작업물을 중심으로 독자적인 포트폴리오를 만든다.

## 2. 현재 상태

현재 저장소는 `create-next-app` 기본 화면에 가까운 초기 상태다.

- `src/app/`에는 공통 레이아웃과 홈 페이지만 존재한다.
- 프로필, 경력, 프로젝트 콘텐츠 모델이 없다.
- 공통 내비게이션, 프로젝트 카드, 필터와 상세 페이지가 없다.
- 기본 metadata와 샘플 이미지가 남아 있다.
- lint와 build 스크립트는 준비되어 있다.

따라서 기존 화면을 확장하기보다 정보 구조, 콘텐츠 모델과 디자인 토큰부터 순서대로 구축한다.

## 3. 제품 목표

### 3.1 핵심 목표

방문자가 짧은 시간 안에 다음 질문에 답을 얻을 수 있는 포트폴리오를 만든다.

1. 이 사람은 누구이며 어떤 일을 하는가?
2. 어떤 프로젝트를 수행했는가?
3. 각 프로젝트에서 맡은 역할과 결과는 무엇인가?
4. 채용 또는 협업을 위해 어떻게 연락할 수 있는가?

### 3.2 사용자 경험 목표

- 첫 화면에서 정체성과 전문 분야를 명확히 전달한다.
- 프로젝트 목록을 카테고리와 검색으로 빠르게 탐색할 수 있게 한다.
- 목록에서 상세 사례로 자연스럽게 이동하게 한다.
- 모바일과 데스크톱에서 동일한 정보 우선순위를 유지한다.
- 과도한 효과보다 콘텐츠 가독성과 세련된 움직임을 우선한다.
- 모든 핵심 기능을 키보드와 보조 기술로 사용할 수 있게 한다.

### 3.3 비목표

초기 버전에서는 다음 항목을 범위에 포함하지 않는다.

- 관리자 페이지 또는 CMS
- 회원가입과 로그인
- 데이터베이스
- 블로그와 댓글
- 방문자 개인화
- 레퍼런스의 코드 또는 에셋 복사
- 검증되지 않은 경력, 성과와 수치 생성

## 4. 레퍼런스에서 적용할 원칙

### 4.1 유지할 경험

- 절제된 다크 테마와 높은 텍스트 대비
- 작은 섹션 라벨과 큰 에디토리얼 제목의 대비
- 데스크톱 상단 내비게이션과 모바일 친화적 내비게이션
- 카테고리 필터와 검색을 결합한 프로젝트 탐색
- 모바일 1열, 넓은 화면 2열의 프로젝트 그리드
- 3:2 비율의 일관된 프로젝트 이미지
- 둥근 이미지 프레임과 최소한의 카드 장식
- 카드 제목, 카테고리, 연도를 빠르게 스캔할 수 있는 구조
- 이미지 확대와 페이드 중심의 짧은 마이크로 인터랙션
- 페이지 하단의 강한 연락 CTA

### 4.2 독자적으로 설계할 요소

- 사이트 이름, 워드마크와 포인트 컬러
- 한국어 중심의 문구와 콘텐츠 톤
- 프로젝트 썸네일과 사례 이미지
- 타이포그래피 조합과 세부 크기 체계
- 프로젝트 카드의 세부 간격과 호버 표현
- 상세 페이지의 스토리텔링 구조
- 연락 방식과 소셜 링크 구성

| 경로 | 목적 | 주요 콘텐츠 |
| --- | --- | --- |
| `/` | 핵심 소개 | 히어로, 간단한 소개, 대표 프로젝트, 전문 분야, 연락 CTA |
| `/about` | 이력 설명 | 소개, 경력, 기술, 교육, 가치관 또는 업무 방식 |

- `sitemap.ts`

## 6. 콘텐츠 모델

반복되는 데이터는 JSX 안에 직접 작성하지 않고 `src/content/`에서 타입과 함께 관리한다.

### 6.1 프로필

- 이름
- 직무 또는 한 줄 소개
- 짧은 소개
- 위치
- 현재 가용 상태
- 프로필 이미지
- 이메일
- 이력서 파일 또는 링크

### 6.2 경력

- 회사 또는 조직
- 역할
- 시작일과 종료일
- 설명
- 검증된 주요 성과
- 사용 기술

### 6.3 프로젝트

프로젝트는 최소한 다음 필드를 가진다.

```ts
type ProjectCategory = "development" | "design" | "other";

type Project = {
  slug: string;
  title: string;
  summary: string;
  year: string;
  categories: ProjectCategory[];
  role: string;
  client?: string;
  duration?: string;
  technologies: string[];
  thumbnail: string;
  thumbnailAlt: string;
  featured?: boolean;
  liveUrl?: string;
  repositoryUrl?: string;
  problem?: string;
  process?: string[];
  outcome?: string;
  images?: Array<{
    src: string;
    alt: string;
    caption?: string;
  }>;
};
```

정보가 준비되지 않은 필드는 사실처럼 채우지 않는다. 화면에서는 `정보 준비 중`과 같은 짧은 placeholder를 사용하거나 선택 필드를 렌더링하지 않는다.

## 7. 화면별 구현 계획

### 7.1 공통 레이아웃

- `html` 언어를 실제 콘텐츠 언어에 맞춘다.
- 공통 `header`, `nav`, `main`, `footer` 구조를 만든다.
- 콘텐츠 최대 너비와 모바일 우선 좌우 여백을 정의한다.
- 현재 경로를 내비게이션에서 텍스트와 시각 요소로 표시한다.
- 데스크톱에서는 상단 고정 내비게이션을 사용한다.
- 모바일 내비게이션은 화면을 가리지 않고 320px에서도 모든 항목을 조작할 수 있게 한다.
- 본문과 하단 CTA가 모바일 내비게이션에 가려지지 않도록 안전 여백을 둔다.

### 7.2 Home

- 이름과 전문 분야를 담은 히어로
- 짧은 자기소개와 About 이동 링크
- 대표 프로젝트 3~4개
- 전문 분야 또는 핵심 기술 요약
- Contact로 연결되는 명확한 CTA

첫 화면에는 이름, 역할과 대표 행동 하나가 반드시 보이도록 한다. 프로젝트 목록 전체를 홈에 중복하지 않는다.

### 7.3 About

- 자기소개
- 현재 역할과 관심 분야
- 시간순 경력
- 기술과 도구
- 교육 또는 자격 정보
- 이력서 다운로드 또는 외부 링크

기술 목록만 나열하지 않고 경력과 프로젝트 맥락에서 역량을 보여준다.

### 7.4 Projects

- 작은 섹션 라벨과 큰 페이지 제목
- `전체`, 카테고리별 필터
- 프로젝트명과 기술을 찾을 수 있는 검색
- 반응형 프로젝트 그리드
- 검색 결과가 없을 때의 빈 상태
- 페이지 하단 연락 CTA

프로젝트 카드 구성:

- 3:2 비율의 썸네일
- 프로젝트명
- 하나 이상의 카테고리
- 연도
- 전체 카드 링크

레이아웃 시작 기준:

- 320px 이상: 1열, 최소 16px 좌우 여백
- 640px 이상: 2열
- 넓은 화면: 프로젝트 콘텐츠는 최대 960px, 헤더와 푸터는 최대 1024px 내에서 유지
- 2열에서는 규칙적인 세로 오프셋을 사용해 리듬을 만들되 읽기 순서는 DOM 순서를 유지

### 7.5 Project detail

- 프로젝트명과 한 줄 설명
- 역할, 기간, 클라이언트, 기술 정보
- 대표 이미지
- 문제 또는 배경
- 접근 방법과 담당 업무
- 주요 화면과 이미지 설명
- 결과와 검증된 성과
- 라이브 사이트와 저장소 링크
- 다른 프로젝트 또는 Contact로 이어지는 다음 행동

`generateStaticParams()` 사용 가능성을 검토하고 존재하지 않는 slug는 `notFound()`로 처리한다.

### 7.6 Contact

- 현재 연락 가능 여부
- 이메일 링크
- GitHub, LinkedIn 등 제공된 소셜 링크
- 이력서 링크
- 짧은 응답 안내

실제 전송이 필요한 폼은 백엔드와 스팸 대응 방안이 정해진 뒤 추가한다. 초기 버전에서는 신뢰할 수 있는 직접 연락 링크를 우선한다.

## 9. 디자인 시스템

### 9.1 색상

- 깊은 중성색 배경
- 높은 대비의 기본 텍스트
- 위계를 구분하는 보조 텍스트
- 개인 브랜드를 위한 하나의 절제된 포인트 컬러
- 카드 이미지별 보조 배경색은 콘텐츠와 조화를 이루는 범위에서 사용

색상만으로 선택, 오류 또는 현재 위치를 전달하지 않는다.

### 9.2 타이포그래피

- 큰 제목용 디스플레이 스타일
- 본문과 UI용 가독성 높은 산세리프
- 반응형 `clamp()`를 사용해 제목 크기의 급격한 변화를 방지
- 본문은 긴 문장에서 읽기 편한 줄 길이와 행간 유지
- 과도한 자간은 짧은 제목과 라벨에만 제한적으로 사용

### 9.3 간격과 형태

- 4px 또는 이에 준하는 일관된 간격 단위
- 큰 섹션 간격과 조밀한 카드 메타 정보의 대비
- 프로젝트 이미지에는 일관된 큰 모서리 반경
- 버튼과 필터는 충분한 클릭 영역 확보
- 장식용 그림자와 테두리는 최소화

## 10. 인터랙션과 모션

- 내비게이션 활성 상태
- 필터 선택 전환
- 검색 열기 또는 입력 상태
- 프로젝트 카드 이미지의 미세한 확대
- 섹션과 카드의 짧은 페이드 또는 이동 진입
- 링크와 버튼의 명확한 hover, focus, active 상태

원칙:

- 콘텐츠를 기다리게 만드는 긴 인트로는 사용하지 않는다.
- 핵심 정보는 JavaScript 또는 애니메이션이 실패해도 보이게 한다.
- `prefers-reduced-motion: reduce`에서는 이동과 확대를 제거하거나 즉시 전환한다.
- 모션 라이브러리 도입 전 CSS와 React/Next.js 내장 기능으로 해결 가능한지 확인한다.

## 11. 접근성 요구사항

- 논리적인 heading 순서 유지
- 모든 이미지에 목적에 맞는 대체 텍스트 제공
- 장식 이미지는 빈 `alt` 사용
- 링크는 이동에, 버튼은 동작에 사용
- 필터는 키보드로 탐색하고 선택할 수 있어야 함
- 선택 상태를 텍스트 또는 접근성 속성으로 전달
- 모든 인터랙티브 요소에 가시적인 focus 스타일 제공
- 본문과 UI 텍스트의 충분한 색상 대비 확보
- 모바일에서 최소 44px 수준의 조작 영역 지향
- 모달 또는 검색 패널을 사용할 경우 포커스 이동과 닫기 동작 제공

## 12. 반응형 요구사항

필수 확인 너비:

- 320px
- 390px
- 640px
- 768px
- 1024px
- 1280px 이상

확인 항목:

- 가로 스크롤이 없음
- 제목과 CTA가 잘리지 않음
- 내비게이션과 필터의 클릭 영역이 겹치지 않음
- 프로젝트 카드 이미지 비율이 유지됨
- 긴 프로젝트명과 다수의 카테고리가 안전하게 줄바꿈됨
- 하단 고정 요소가 콘텐츠와 링크를 가리지 않음

## 13. 성능과 SEO

### 13.1 성능

- 프로젝트 이미지는 `next/image` 사용
- 이미지 `sizes`, 너비, 높이 또는 비율 명시
- 첫 화면의 핵심 이미지에만 `priority` 적용
- 프로젝트 목록 전체 이미지를 무조건 preload하지 않음
- 불필요한 Client Component와 전역 상태 제거
- 새 의존성 추가 전 기존 기능과 내장 API 확인
- 레이아웃 이동과 긴 메인 스레드 작업 최소화

### 13.2 SEO

- 루트와 페이지별 고유 title, description
- 프로젝트 상세별 동적 metadata
- Open Graph 제목, 설명과 이미지
- canonical URL 전략
- `sitemap.ts`에 정적 페이지와 프로젝트 slug 포함
- `robots.ts` 제공
- 실제 공개 정보만 구조화 데이터에 포함

## 14. 개발 단계

### 단계 0. 콘텐츠 준비

- 실제 프로필 정보 수집
- 경력과 교육 정보 확인
- 공개할 프로젝트 선정
- 프로젝트별 역할, 과정과 결과 정리
- 썸네일과 상세 이미지 준비
- 이메일과 소셜 링크 확인

완료 조건:

- 공개 가능한 연락 수단이 확정된다.
- 사실 확인이 필요한 항목과 placeholder가 구분된다.

### 단계 1. 기반과 디자인 토큰

- 기본 템플릿 제거
- 전역 metadata와 언어 설정
- 색상, 타이포그래피, 간격 토큰 정의
- 공통 컨테이너와 focus 스타일
- 공통 헤더, 내비게이션, 푸터, CTA
- `src/content/` 타입과 데이터 구조

완료 조건:

- 모든 예정 경로에서 공통 레이아웃이 일관되게 보인다.
- 320px에서 내비게이션과 기본 레이아웃이 깨지지 않는다.

### 단계 2. Projects MVP

- Projects 히어로
- 프로젝트 카드와 그리드
- 카테고리 필터
- 검색
- 빈 결과 상태
- 모바일과 데스크톱 레이아웃

완료 조건:

- 이미지 로딩으로 레이아웃이 흔들리지 않는다.

### 단계 3. Project detail

- 동적 slug 라우트
- 상세 콘텐츠 레이아웃
- 외부 링크와 이미지 갤러리
- 프로젝트별 metadata
- 존재하지 않는 slug의 404 처리

완료 조건:

- 모든 프로젝트 카드가 올바른 상세 페이지로 이동한다.
- 직접 URL 접근과 새로고침이 정상 작동한다.
- 선택 필드가 없는 프로젝트도 레이아웃이 깨지지 않는다.

### 단계 4. Home, About, Contact

- Home 소개와 대표 프로젝트
- About 경력과 기술
- Contact 연락 정보
- 페이지 간 CTA 연결

완료 조건:

- Home에서 프로젝트 상세와 Contact까지 자연스럽게 이동할 수 있다.
- 중복 콘텐츠는 공통 데이터에서 렌더링된다.

### 단계 5. 모션, 접근성, SEO와 최종 QA

- 진입과 hover 모션
- reduced motion 대응
- 키보드 탐색과 focus 확인
- metadata, Open Graph, sitemap, robots
- 모바일과 데스크톱 시각 검수
- lint와 production build 검증

완료 조건:

- 핵심 사용자 흐름에 차단 요소가 없다.
- 필수 반응형 너비에서 레이아웃 문제가 없다.
- lint와 build가 성공한다.

## 16. 검증 계획

자동 검증:

```bash
npm run lint
npm run build
```

필요한 테스트를 추가했다면 해당 테스트 명령도 함께 실행한다.

수동 검증 흐름:

1. Home에서 대표 프로젝트를 선택한다.
2. 프로젝트 상세 내용을 확인한다.
3. Projects로 이동해 카테고리 필터를 변경한다.
4. 검색 결과와 빈 결과 상태를 확인한다.
5. Contact CTA와 이메일 또는 소셜 링크를 확인한다.
6. 같은 흐름을 모바일과 데스크톱 너비에서 반복한다.
7. 키보드만 사용해 내비게이션, 필터와 링크를 조작한다.
8. reduced motion 환경에서 불필요한 움직임이 제거되는지 확인한다.

## 17. 주요 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 실제 콘텐츠 부족 | 정보를 꾸미지 않고 placeholder를 명확히 표시 |
| 레퍼런스와 과도하게 유사해짐 | 브랜드, 타이포그래피, 카피, 이미지와 세부 레이아웃을 독자적으로 설계 |

| 필터를 위해 전체 페이지가 Client Component가 됨 | 프로젝트 탐색 영역만 작은 클라이언트 경계로 분리 |

| 상세 콘텐츠 형식이 프로젝트마다 다름 | 공통 필수 필드와 선택 섹션을 분리해 모델링 |
